# Выпуск

Заполнение `.env` и выкатка. Выпуск — одна команда:

```bash
make deploy SERVER=deploy@<IP>
```

Машина должна быть подготовлена — [server.md](server.md).

---

## 1. `.env`

### Файлов два, и это разные файлы

| Файл | Где | Что в нём |
|---|---|---|
| `.env` | ваша машина | разработка, `pnpm dev`. Для выпуска не используется |
| `.env.deploy` | ваша машина | **две** строки: продовые `SITE_URL` и `PUBLIC_API_URL` |
| `.env` | сервер, `~/noova/` | вся продовая конфигурация и секреты |

Секреты на сервер не копируются — они там и рождаются. `make deploy` серверный
файл не создаёт и не перезаписывает, меняет только `IMAGE_TAG` и `IMAGE_PREFIX`.

**Локально:**

```bash
cat > .env.deploy <<'EOF'
SITE_URL=https://noova.cc
PUBLIC_API_URL=https://noova.cc
EOF
```

Только эти две переменные запекаются в браузерный бандл на сборке. Остальное
compose подставит на сервере — предупреждение сборки про неустановленные
`MINIO_ROOT_USER`, `SITE_DOMAIN` и прочие ожидаемо.

**На сервере:**

```bash
make server-env SERVER=deploy@<IP> DOMAIN=noova.cc EMAIL=admin@example.com
```

Существующий файл скрипт **не перезаписывает**: смена `POSTGRES_PASSWORD`
оставила бы базу недоступной вместе со всеми данными.

> Сделайте копию `.env` вне сервера. Без `POSTGRES_PASSWORD` дамп базы не
> восстановить — бэкапы окажутся бесполезны ровно тогда, когда понадобятся.

То же вручную:

```bash
ssh deploy@<IP>
mkdir -p ~/noova && cd ~/noova
DOMAIN=noova.cc          # ваш домен
EMAIL=admin@example.com  # для писем Let's Encrypt

cat > .env <<EOF
SITE_DOMAIN=$DOMAIN
SITE_URL=https://$DOMAIN
PUBLIC_API_URL=https://$DOMAIN
MEDIA_BASE_URL=https://$DOMAIN/media
ACME_EMAIL=$EMAIL

POSTGRES_USER=noova
POSTGRES_DB=noova
POSTGRES_PASSWORD=$(openssl rand -base64 32 | tr -d '/+=')
MINIO_ROOT_USER=noova-minio
MINIO_ROOT_PASSWORD=$(openssl rand -base64 32 | tr -d '/+=')

IP_HASH_SALT=$(openssl rand -hex 32)
INTERNAL_API_TOKEN=$(openssl rand -hex 32)
REVALIDATE_SECRET=$(openssl rand -hex 32)

MAIL_DOMAIN=$DOMAIN
MAIL_FROM="Noova <noreply@$DOMAIN>"

IMAGE_PREFIX=noova
IMAGE_TAG=latest
EOF
chmod 600 .env
```

`tr -d '/+='` обязателен: пароль Postgres уходит в строку подключения, и слэш
с плюсом её ломают.

### Обязательные переменные

У них нет значений по умолчанию, пустыми они ломают стек.

| Переменная | Что ставить |
|---|---|
| `SITE_DOMAIN` | `noova.cc` — без схемы |
| `SITE_URL` | `https://noova.cc` |
| `PUBLIC_API_URL` | `https://noova.cc` — API на том же домене |
| `MEDIA_BASE_URL` | `https://noova.cc/media` |
| `ACME_EMAIL` | ваш адрес — туда придут письма об истечении сертификата |
| `POSTGRES_USER` / `POSTGRES_DB` | `noova` |
| `POSTGRES_PASSWORD` | `openssl rand -base64 32`, без `/`, `+`, `=` |
| `MINIO_ROOT_USER` | любое имя, не `noova` |
| `MINIO_ROOT_PASSWORD` | `openssl rand -base64 32` |
| `IP_HASH_SALT` | `openssl rand -hex 32` |
| `REVALIDATE_SECRET` | `openssl rand -hex 32` |
| `INTERNAL_API_TOKEN` | `openssl rand -hex 32` |
| `MAIL_DOMAIN` | `noova.cc` |
| `MAIL_FROM` | `"Noova <noreply@noova.cc>"` |

**Три последних секрета обязаны быть случайными.** По `IP_HASH_SALT` адреса
восстанавливаются из журналов перебором; по `INTERNAL_API_TOKEN` любой снимает
себе лимит запросов; по `REVALIDATE_SECRET` — сбрасывает кэш сайта в цикле.

### Чего в серверном `.env` быть не должно

> **`SMTP_*` — опасное исключение.** Compose берёт их из `.env`, если они там
> есть, и только иначе подставляет свой Postfix (`smtp:587` без аутентификации).
> В `.env.example` они стоят в `localhost:1025` — это Mailpit для разработки.
> Скопируете пример на сервер целиком — API начнёт стучаться в самого себя, и
> письма молча перестанут уходить. `make-env.sh` их не пишет намеренно.

**`RELAY_*` — внешний релей**, когда провайдер не открывает 25-й порт. Задаются
только в этом случае, пустые означают «отправлять напрямую»:

| Переменная | Пример |
|---|---|
| `RELAY_HOST` | `[smtp.eu.mailgun.org]:587` — квадратные скобки обязательны |
| `RELAY_USER` | `noreply@noova.cc` — обязан совпадать с адресом в `MAIL_FROM` |
| `RELAY_PASSWORD` | пароль SMTP-учётки релея, не пароль от кабинета |
| `RELAY_TLS_LEVEL` | `encrypt` — с релеем обязательно, иначе пароль уйдёт открытым |

Релей прописывается Postfix'у, а не в `SMTP_HOST` у `api`: так письмо
по-прежнему подписывается нашим DKIM-ключом, DMARC проходит по своему домену,
и смена релея не требует правок в DNS. Подробнее — [server.md](server.md) §4.

**Не используются на сервере** (нужны только для запуска вне контейнеров):
`DATABASE_URL`, `REDIS_URL`, `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`,
`WEB_REVALIDATE_URL`. Доступ к хранилищу api и jobs получают по
`MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`.

**Выводятся из других и не читаются из `.env`:** `CORS_ORIGINS`,
`NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_MEDIA_URL` —
compose берёт их из `SITE_URL` и `PUBLIC_API_URL`.

> `NEXT_PUBLIC_MEDIA_URL` нужна **на сборке**: `next.config.ts` строит из неё
> `images.remotePatterns`. Не доехала — оптимизатор ответит `"url" parameter is
> not allowed` на каждую фотографию, и лечится это только пересборкой.

**Со значениями по умолчанию, трогать незачем:** `LOG_LEVEL`, `S3_BUCKET`,
`S3_REGION`, `RETENTION_*`, `JOBS_INTERVAL_SECONDS`, `BACKUP_*`, `RATE_LIMIT_*`.

**Карта.** `make-env.sh` подставляет публичный сервер OpenStreetMap и собирает
`MAP_TILE_USER_AGENT` из домена и почты: политика OSMF требует понятный
User-Agent и блокирует безымянные без предупреждения. Пустой `MAP_TILE_URL`
выключает карты. Смена поставщика — L-06 в `documentation/planning/legal.md`.

## 2. `make deploy`

Собирает у вас, привозит на сервер, запускает и проверяет. Ни git, ни
исходников, ни учётной записи GitHub на сервере не нужно — едут готовые образы,
`docker-compose.yml`, `Caddyfile` и скрипты бэкапа.

Внутри — `scripts/deploy.sh`. Сверх ручных шагов он делает пять вещей:

1. **Типы и тесты до сборки.** Сборка идёт под чужую платформу через эмуляцию
   и занимает десятки минут; узнавать о падающем тесте после неё — терять их
   впустую. Линтер не входит намеренно (есть предсуществующие замечания, и
   выпуск, падающий на них, начнут обходить флагом — а с ними и тесты).
   Аварийный обход: `SKIP_TESTS=1 make deploy SERVER=…`.
2. **Проверки окружения** — `SITE_URL`, доступ по ssh, наличие `.env` на
   сервере, архитектура машины.
3. **Тег по коммиту.** `IMAGE_TAG` из `git rev-parse --short HEAD`, грязное
   дерево получает суффикс `-dirty`. Запись тега идёт тем же ssh-сеансом, что и
   загрузка образов: раздельно обрыв связи давал успешный на вид выпуск без
   изменений.
4. **Дамп базы перед миграциями.** `prisma migrate deploy` необратим.
   Пропускается на первом выпуске, когда контейнера `backup` ещё нет.
5. **Сверка запущенного с привезённым** и запрос снаружи — выпуск может
   оборваться между переносом образов и запуском.

### Платформа: Apple Silicon против x86-сервера

Docker молча собирает под платформу машины сборки. Образ с arm64 на x86-сервере
падает с `exec format error`, причём сборка и перенос до этого проходят
«успешно». Скрипт спрашивает `uname -m` у сервера, выставляет
`DOCKER_DEFAULT_PLATFORM` и проверяет архитектуру готового образа.

Плата — скорость: эмуляция превращает пару минут в десятки. Альтернативы —
сборка в CI (раннеры amd64) или прямо на сервере.

### Шум в логе сборки — норма

`next build` пререндерит страницы, API в этот момент нет, и на каждую из 47
страниц в лог падает:

```
[api] headerCatalog недоступен, отдаём запасное значение TypeError: fetch failed
```

Так задумано — `safely()` в `apps/web/src/shared/api.ts`. Страницы собираются с
запасными значениями, ISR подтягивает данные на первом цикле. Смотреть в логе
надо на строки `ERROR` и `error:` от buildx.

### Что происходит на сервере

1. Postgres, Redis, MinIO — с проверками готовности.
2. `migrate` накатывает миграции отдельным контейнером: при нескольких репликах
   `api` они подрались бы за блокировку. `prisma migrate deploy` идемпотентен.
3. `minio-init` создаёт бакет и открывает анонимное чтение **только** префикса
   `public/`; непроверенные фотографии остаются в `pending/`.
4. `api` — после обоих, `web` — после healthcheck `api`.
5. `caddy` выпускает сертификат и проксирует: `/api/*` и `/healthz` в `api`,
   `/media/*` в MinIO, остальное в `web`.

Наружу смотрит только Caddy.

### Тег образа

Ставьте по коммиту, а не `latest`: тогда откат — это правка одной строки в
`.env` и `docker compose up -d`. `latest` не даёт ответить на вопрос «что
сейчас запущено».

### `make update` — применить то, что уже на сервере

```bash
make update SERVER=deploy@<IP>
```

`docker compose up -d --no-build`. Нужен, когда изменилось окружение, а не код:
правка `.env`, новый `Caddyfile`, изменения в `docker-compose.yml`.

Отдельные шаги цепочки — `make images`, `make images-ship SERVER=…`,
`make images-push`, `make deploy-files SERVER=…` — нужны только при разборе
неполадок.

## 3. Справочники

Миграции создают пустые таблицы. Без городов, районов и услуг не пройти
регистрацию: список городов приходит пустым.

```bash
ssh deploy@<IP> "cd noova && docker compose exec api node dist/scripts/seed-reference.js"
```

Идемпотентно. `make deploy` делает это сам после того, как стек стал healthy.

| | Куда | Почему |
|---|---|---|
| услуги, города, районы | прод | без них не работает регистрация и фильтры |
| анкеты, учётные записи, промо-слоты | только разработка | на проде их создают люди |

### Обратное направление: выгрузка в репозиторий

Справочники заводятся из админки, то есть их источник — база. Чтобы обнуление
сервера их не стёрло:

```bash
# на сервере, после правок в админке
docker compose exec api node dist/scripts/export-reference.js
# файл prisma/reference-data.ts забрать к себе и закоммитить
```

Локально — `pnpm --filter @noova/api db:export:reference`.

Идентификаторы выгружаются вместе с данными и проставляются при создании:
справочник на чистой машине получает те же id, иначе ссылки на него указывали
бы в пустоту.

> **Правки в админке без выгрузки живут до следующего выпуска.** `make deploy`
> накатывает справочник из файла и вернёт отключённый город обратно. Порядок:
> поправили в админке → выгрузили → закоммитили.

Источники — `prisma/locations.ts`, `prisma/services.ts`,
`prisma/reference-translations.ts`. Названия хранятся переводами на три языка
(N-35), неполный перевод не сохраняется. Выпавшие из справочника услуги и
районы деактивируются, а не удаляются: на них могут ссылаться анкеты.

## 4. Первый администратор

```bash
ssh deploy@<IP> "cd noova && docker compose exec api node dist/scripts/create-admin.js <email> '<пароль>'"
```

Разово, после первого успешного выпуска. Внутри контейнера — снаружи базы не
видно. Пароль не короче 10 символов. Повторный запуск на существующем адресе
завершится ошибкой: повышать обычного пользователя до администратора этот
сценарий намеренно не умеет.

## 5. Если выпуск не удался

```bash
ssh deploy@<IP> 'cd noova && docker compose logs -f api migrate'
make rollback SERVER=deploy@<IP> TAG=<тег прошлого выпуска>
```

Автоматического отката нет намеренно: миграции к тому моменту применены, и
вернуть образ на схему прошлого выпуска — значит получить код и базу вразнобой.
Скрипт печатает готовую команду и оставляет решение за вами.

**Откат кода — одна строка, откат миграции — нет.** Prisma не умеет откатывать
`migrate deploy`, поэтому миграции, удаляющие колонки или данные, разносятся на
два выпуска: перестать пользоваться → выпустить → убедиться → удалить. Так
сделано с `Profile.nationality`.

Дамп перед миграциями `make deploy` снимает сам; вручную — `make backup`.
Другого способа вернуться после неудачной миграции нет.

# Развёртывание

Что нужно кроме сервера, как поднять стек, как заполнить `.env`, как
посмотреть базу и как забрать бэкап.

---

## 1. Что нужно, кроме сервера

Почти всё внутри стека: хранилище файлов (MinIO), база, Redis и TLS —
свои. Снаружи нужны немногие вещи, и для стенда разработки — ещё меньше.

| | Стенд | Прод | Комментарий |
|---|---|---|---|
| Домен и DNS | нужен | нужен | Njalla подходит |
| Сервер | 4 ГБ / 2 vCPU | 8 ГБ / 4 vCPU | см. §2 |
| Порт 25 наружу | нужен | нужен | иначе не уходит почта |
| PTR (обратный DNS) | желателен | нужен | ставит провайдер, не в DNS-панели |
| SPF, DKIM, DMARC | желательны | нужны | см. §5 |
| Тайл-сервер карт | можно без | нужен | L-06 в `legal.md` |
| Платёжный процессор | нет | нужен | вместе с N-30 |
| Место для бэкапов вне сервера | желательно | обязательно | N-29 |
| Хранилище файлов | своё | своё | MinIO в стеке |
| TLS-сертификат | Caddy | Caddy | бесплатно, автоматически |

**Ничего платного, кроме домена и сервера, для стенда не требуется.**

### Домен на Njalla

Njalla регистрирует домен **на себя** и передаёт право пользования — в этом
и смысл сервиса, но помните: в реестре владелец не вы, и перенос к другому
регистратору позже будет отдельной процедурой. Их DNS годится: нужны `A`
(и `AAAA`, если есть IPv6) на адрес сервера.

### Выбор провайдера

Главный критерий — **не приём криптовалюты, а правила по содержимому**.
Крипту берут многие; приостановка учётной записи из-за взрослого каталога
опаснее любой DDoS-атаки: сайт не просто ляжет, пропадёт доступ к машине
с данными.

До оплаты найдите в условиях провайдера явное разрешение на adult-контент
и убедитесь, что нет оговорки «по нашему усмотрению». Отдельно спросите про
**порт 25** — многие закрывают его по умолчанию, а некоторые не открывают
вовсе. Проверять это надо до оплаты, а не после переезда.

Правовая сторона выбора юрисдикции — L-09 в `legal.md`.

## 2. Мощности

Девять контейнеров: postgres, redis, minio, api, web, caddy, smtp, jobs,
backup.

- **RAM 4 ГБ — минимум, не запас.** У `api` стоит потолок 768 МБ
  (`under-pressure` отдаёт 503 вместо падения по памяти), Next в standalone
  берёт 200–300 МБ, Postgres около 256 МБ, столько же MinIO. Обработка фото
  через sharp даёт короткие всплески. На 2 ГБ стек заведётся, но начнёт
  свопить на первой же загрузке снимков.
- **Диск.** Три размера на снимок в WebP — примерно 300 КБ на фотографию,
  до 20 фото на анкету, то есть около 6 МБ. Тысяча анкет ≈ 6 ГБ плюс дампы.
  80 ГБ NVMe хватит надолго.

## 3. Развёртывание

```bash
git clone <repo> && cd noova
cp .env.example .env      # заполнить по §4
docker compose up -d --build
```

Порядок запуска стек держит сам:

1. Поднимаются Postgres, Redis, MinIO — с проверками готовности.
2. `migrate` накатывает миграции; отдельным контейнером, потому что при
   нескольких репликах `api` они подрались бы за блокировку.
3. `minio-init` создаёт бакет и открывает анонимное чтение **только**
   префикса `public/`. Непроверенные фотографии лежат в `pending/` и
   остаются недоступными по прямой ссылке.
4. `api` стартует после обоих, `web` — после healthcheck `api`.
5. `caddy` выпускает сертификат и проксирует: `/api/*` и `/healthz` в `api`,
   `/media/*` в MinIO, остальное в `web`.

Наружу смотрит только Caddy — остальные сервисы портов не публикуют.

Первый администратор создаётся разово:

```bash
docker compose exec api node -e "require('./dist/server.js')" # стек уже поднят
pnpm --filter @noova/api db:create-admin <email> <пароль>
```

Проверка после запуска:

```bash
docker compose ps                      # все healthy
curl -I https://<домен>                # 200 и валидный TLS
docker compose logs -f api             # ошибок нет
```

### Переезд на другой домен

Поменять `SITE_DOMAIN` / `SITE_URL` в `.env` и перезапустить:
`docker compose up -d --force-recreate caddy web`. Сертификат выпустится сам.

## 4. Заполнение `.env`

Файл общий для локальной разработки и сервера, но переменные разные.
**На сервере обязательны эти:**

| Переменная | Что ставить |
|---|---|
| `SITE_DOMAIN` | `noova.cc` — без схемы |
| `SITE_URL` | `https://noova.cc` |
| `PUBLIC_API_URL` | `https://noova.cc` — API на том же домене |
| `NEXT_PUBLIC_SITE_URL` | то же, что `SITE_URL` |
| `NEXT_PUBLIC_API_URL` | то же, что `PUBLIC_API_URL` |
| `NEXT_PUBLIC_MEDIA_URL` | `https://noova.cc` |
| `MEDIA_BASE_URL` | `https://noova.cc/media` |
| `ACME_EMAIL` | ваш адрес — туда придут письма об истечении сертификата |
| `POSTGRES_PASSWORD` | `openssl rand -base64 32` |
| `MINIO_ROOT_USER` | любое имя, не `noova` |
| `MINIO_ROOT_PASSWORD` | `openssl rand -base64 32` |
| `IP_HASH_SALT` | `openssl rand -hex 32` |
| `REVALIDATE_SECRET` | `openssl rand -hex 32` |
| `INTERNAL_API_TOKEN` | `openssl rand -hex 32` |
| `MAIL_DOMAIN` | `noova.cc` |
| `MAIL_FROM` | `"Noova <noreply@noova.cc>"` |
| `CORS_ORIGINS` | `https://noova.cc` |

**Три секрета обязаны быть случайными.** Оставить значения из примера —
значит: по `IP_HASH_SALT` восстанавливаются адреса из журналов перебором;
по `INTERNAL_API_TOKEN` любой снимает себе лимит запросов; по
`REVALIDATE_SECRET` любой сбрасывает кэш сайта в цикле.

**Что на сервере не используется** (нужно только для локального запуска
вне контейнеров): `DATABASE_URL`, `REDIS_URL`, `S3_ENDPOINT`,
`S3_ACCESS_KEY`, `S3_SECRET_KEY`, `SMTP_HOST`, `SMTP_PORT`,
`WEB_REVALIDATE_URL`. В контейнерах эти значения задаёт
`docker-compose.yml`, и правки в `.env` на них не влияют — доступ к
хранилищу api и jobs получают по `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`.

`S3_BUCKET` и `S3_REGION` на сервере читаются, но имеют разумные значения
по умолчанию (`noova-media`, `us-east-1`) — трогать их незачем.

**Необязательные:** `MAP_TILE_URL` (пусто — карты выключены, остаётся
текстовая сноска), сроки хранения `RETENTION_*`, `JOBS_INTERVAL_SECONDS`,
`BACKUP_*`, `RATE_LIMIT_*` — у всех разумные значения по умолчанию.

## 5. Почта

Мы поднимаем **свой Postfix** (контейнер `smtp`): SendGrid, Mailgun и
подобные ограничивают взрослый контент в условиях использования (решение
из N-15). Плата за это — настройка доставляемости вручную.

Без почты не пройти регистрацию: подтверждение адреса и сброс пароля
уходят письмом.

**1. Порт 25 наружу.** Самая частая причина «письма не приходят».
Открывается заявкой в поддержку провайдера.

**2. PTR-запись** для IP → `mail.<домен>`. Ставится у провайдера, **не**
в DNS-панели. Без неё большинство почтовых серверов отправит письма в спам.

**3. Четыре записи в DNS:**

| Тип | Имя | Значение |
|---|---|---|
| A | `mail` | IP сервера |
| TXT | `@` | `v=spf1 a mx ~all` |
| TXT | `mail._domainkey` | из контейнера, см. ниже |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:admin@<домен>` |

DKIM-ключ генерируется сам при первом запуске (`DKIM_AUTOGENERATE`).
Публичную часть достать так:

```bash
docker compose exec smtp sh -c 'ls -R /etc/opendkim/keys && cat /etc/opendkim/keys/*/*.txt'
```

Содержимое `.txt` — готовая DNS-запись.

**Проверьте репутацию IP** до того, как привязывать домен: свежий адрес
нередко уже в чёрных списках от прежнего арендатора, и менять его после
настройки всего остального — потерянный день.

## 6. Как посмотреть базу

### Быстро, прямо на сервере

```bash
# список таблиц
docker compose exec postgres psql -U noova -d noova -c '\dt'

# сколько строк в каждой
docker compose exec postgres psql -U noova -d noova -c \
  "select relname, n_live_tup from pg_stat_user_tables order by n_live_tup desc;"

# произвольный запрос
docker compose exec postgres psql -U noova -d noova -c \
  "select slug, status from \"Profile\" limit 20;"

# интерактивно
docker compose exec -it postgres psql -U noova -d noova
```

Полезное в `psql`: `\dt` — таблицы, `\d "Profile"` — колонки таблицы,
`\q` — выход.

### Графически, через Prisma Studio

**Порт наружу не открывать.** Пробросьте его по SSH и откройте у себя:

```bash
ssh -L 5555:localhost:5555 user@сервер
# в другом терминале, на сервере:
docker compose exec api npx prisma studio --port 5555
```

Дальше `http://localhost:5555` у себя в браузере. Соединение идёт по SSH,
наружу ничего не смотрит.

> Открытый порт Postgres или Studio наружу — прямой доступ ко всей базе
> с особой категорией персональных данных. Только SSH-туннель.

## 7. Бэкапы

Контейнер `backup` делает `pg_dump` по расписанию
(`BACKUP_INTERVAL_SECONDS`, по умолчанию раз в сутки) в `./backups/`
на хосте, с ротацией на `BACKUP_KEEP_DAYS` дней. Дамп пишется во временный
файл и переименовывается в конце — оборванный процесс не оставит битый файл,
выглядящий как валидный.

```bash
make backup                    # дамп прямо сейчас
ls -lh backups/                # что есть
scp user@сервер:~/noova/backups/noova-*.sql.gz .   # забрать к себе
make restore DUMP=backups/noova-20260821T120000Z.sql.gz
```

Восстановление перезаписывает базу и требует подтверждения `yes`.

### Чего в бэкапе пока нет

**Фотографии не бэкапятся.** Том `minio_data` в дамп не входит:
восстановление даст анкеты, ссылающиеся на несуществующие снимки.
Задача — N-29.

### Про мотивацию

DDoS данные не стирает — он делает сайт недоступным. Данные теряются от
приостановки провайдером, отказа диска или ошибки оператора. От этого
спасает не локальный дамп, а **зашифрованная копия на другой машине**,
причём ключ шифрования не должен лежать на том же сервере: иначе
шифрование защищает ровно от того, чего не случится.

> Дампы содержат персональные данные особой категории по GDPR. Каталог
> `backups/` в git не попадает; на сервере его нужно шифровать и хранить
> отдельно от основной машины.

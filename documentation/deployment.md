## 1. Как посмотреть базу

### Быстро, прямо на сервере

```bash
# список таблиц
docker compose exec postgres psql -U noova -d noova -c '\dt'

# сколько строк в каждой
docker compose exec postgres psql -U noova -d noova -c \
  "select relname, n_live_tup from pg_stat_user_tables order by n_live_tup desc;"

# произвольный запрос
docker compose exec postgres psql -U noova -d noova -c \
  "select slug, status from \"Profile\" limit 20;"

# интерактивно
docker compose exec -it postgres psql -U noova -d noova
```

Полезное в `psql`: `\dt` — таблицы, `\d "Profile"` — колонки таблицы,
`\q` — выход.

### Графически, через Prisma Studio

**Порт наружу не открывать.** Пробросьте его по SSH и откройте у себя:

```bash
ssh -L 5555:localhost:5555 user@сервер
# в другом терминале, на сервере:
docker compose exec api npx prisma studio --port 5555
```

Дальше `http://localhost:5555` у себя в браузере. Соединение идёт по SSH,
наружу ничего не смотрит.

> Открытый порт Postgres или Studio наружу — прямой доступ ко всей базе
> с особой категорией персональных данных. Только SSH-туннель.

## 2. Бэкапы

Контейнер `backup` делает `pg_dump` по расписанию
(`BACKUP_INTERVAL_SECONDS`, по умолчанию раз в сутки) в `./backups/`
на хосте, с ротацией на `BACKUP_KEEP_DAYS` дней. Дамп пишется во временный
файл и переименовывается в конце — оборванный процесс не оставит битый файл,
выглядящий как валидный.

```bash
make backup                    # дамп прямо сейчас
ls -lh backups/                # что есть
scp user@сервер:~/noova/backups/noova-*.sql.gz .   # забрать к себе
make restore DUMP=backups/noova-20260821T120000Z.sql.gz
```

Восстановление перезаписывает базу и требует подтверждения `yes`.

### Чего в бэкапе пока нет

**Фотографии не бэкапятся.** Том `minio_data` в дамп не входит:
восстановление даст анкеты, ссылающиеся на несуществующие снимки.
Задача — N-29.

### Про мотивацию

DDoS данные не стирает — он делает сайт недоступным. Данные теряются от
приостановки провайдером, отказа диска или ошибки оператора. От этого
спасает не локальный дамп, а **зашифрованная копия на другой машине**,
причём ключ шифрования не должен лежать на том же сервере: иначе
шифрование защищает ровно от того, чего не случится.

> Дампы содержат персональные данные особой категории по GDPR. Каталог
> `backups/` в git не попадает; на сервере его нужно шифровать и хранить
> отдельно от основной машины.

## 3. Переезд на другой домен

Поменять `SITE_DOMAIN` / `SITE_URL` в `.env` на сервере и перезапустить:
`docker compose up -d --force-recreate caddy web`. Сертификат выпустится сам.

Адреса запекаются в браузерный бандл на сборке, поэтому вместе с этим
обновите `.env.deploy` у себя и выпустите заново — иначе фронт продолжит
ходить на старый домен. Подробности — [release.md](release.md) §1.

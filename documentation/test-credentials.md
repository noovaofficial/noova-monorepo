# Учётные записи для локальной проверки

> **Только для разработки на своей машине.**
> Пароли здесь лежат открытым текстом намеренно — это одноразовые учётки
> локального стенда. Ни один из этих адресов и паролей не должен появиться
> на сервере, доступном извне. Скрипт, который их создаёт, отказывается
> работать при `NODE_ENV=production`.

Создать или вернуть в исходное состояние:

```bash
pnpm --filter @noova/api db:seed:dev-users
```

Скрипт идемпотентен: перезапуск возвращает пароли и роли к значениям из
таблицы, даже если их успели поменять. Почта у всех считается подтверждённой.

## Учётки

| Роль | Email | Пароль | Что доступно |
|---|---|---|---|
| Администратор | `admin@noova.local` | `admin-password-1` | Всё: очередь модерации, `/admin` — управление сотрудниками |
| Модератор | `mod@noova.local` | `moderator-pass-1` | Очередь `/moderation`: фото, верификация, пользователи |
| Индивидуальная анкета | `individual@noova.local` | `individual-pass-1` | Кабинет, **одна** анкета вида `escort` |
| Салон | `salon@noova.local` | `salon-pass-secret` | Кабинет, **несколько** анкет вида `massage` |
| Клиент | `client@noova.local` | `client-pass-secret` | Никнейм `tester`; избранное и комментарии — когда появятся |

Первый администратор на чистой базе создаётся отдельно:

```bash
pnpm --filter @noova/api db:create-admin <email> <пароль>
```

## Что где смотреть

| Раздел | Адрес | Кто видит |
|---|---|---|
| Каталог | `/ru` | все |
| Вход и регистрация | `/ru/login`, `/ru/register` | все |
| Кабинет владельца | `/ru/account/profiles` | `advertiser` |
| Очередь модерации | `/ru/moderation` | `moderator`, `admin` |
| Сотрудники | `/ru/admin` | `admin` |

Разделы закрыты не только в интерфейсе: роль проверяется на сервере, поэтому
прямой запрос к API отдаёт 403.

## Письма

Локально их принимает Mailpit из `docker-compose.dev.yml`. Все письма —
подтверждение адреса, сброс пароля, уведомление о попытке регистрации на
занятый адрес — открываются в браузере:

**<http://localhost:8025>**

Настоящая почта никуда не уходит, ссылки рабочие. В логи приложения ни тело
письма, ни токен не попадают — это намеренно.

Подтвердить адрес можно и вручную, без письма: `/ru/moderation` → вкладка
«Пользователи» → «Подтвердить почту». Действие пишется в журнал модерации.

Сотрудника создаёт админ в `/ru/admin`; пароль в форме показан открыто и
передаётся лично — письма о заведении учётки не предусмотрено.

## Демо-данные каталога

```bash
pnpm --filter @noova/api db:seed:services   # справочник услуг, безопасен для прода
pnpm --filter @noova/api db:seed            # 20 анкет и 10 салонов в Берлине
```

Общий сид убирает за собой только собственные демо-анкеты и живые учётные
записи не трогает — но всё равно предназначен для локальной базы.

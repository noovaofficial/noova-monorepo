  Файл: `apps/api/src/modules/videos/ffmpeg.ts`.

## 2. Безопасность приложения

### P1

- [ ] **Правки опубликованной анкеты не проходят модерацию.**
  Имя и описание можно поменять после одобрения, и они сразу попадают на
  витрину: модератор одобряет один текст, посетитель видит другой. Именно это
  делало XSS из раздела 1 легко эксплуатируемой.
  Варианты: (а) возвращать анкету на проверку при правке текста; (б) оставлять
  опубликованной, но ставить правку в очередь модератора постфактум.
  Где: `PATCH /me/profiles/:id` в `apps/api/src/modules/account/routes.ts`.
  _Решение владельца продукта, 15.11.2026: вариант (б)_ — анкета остаётся
  опубликованной, правка имени и описания попадает в очередь модератора
  постфактум. Не реализовано.
- [x] **API ходит в MinIO под root-учёткой.** `S3_ACCESS_KEY` в
  `docker-compose.yml` — это `MINIO_ROOT_USER`. Компрометация API даёт полный
  контроль над хранилищем, включая снимки документов верификации.
  Сделать: отдельный ключ с правами только на бакет, создавать в `minio-init`.
  _Сделано 15.11.2026, не закоммичено._ `minio-init` заводит учётку `MINIO_APP_USER` с правами только на объекты бакета; api и jobs работают под ней. Проверено на временном стенде: чтение, запись и копирование проходят, админ-команды и чужие бакеты закрыты, повторный запуск без ошибок. **Перед выкатом добавить в `.env` на сервере `MINIO_APP_USER` и `MINIO_APP_PASSWORD`** — без них compose не стартует.

### P2

- [ ] **Нет Content-Security-Policy.** Ни на сайте (`apps/web/next.config.ts`),
  ни на API (в helmet отключена, `apps/api/src/plugins/security.ts`). CSP
  превращает любую XSS из «полный доступ к учётке» в «ничего не произошло».
  Мешают инлайн-скрипты темы и возрастного гейта в
  `apps/web/src/app/[locale]/layout.tsx` — понадобятся nonce.
- [ ] **У сотрудников нет второго фактора.** Админ и модератор входят тем же
  паролем и восстанавливают его той же почтой, что обычные пользователи; взлом
  почты админа даёт всё. Сделать: TOTP для ролей `admin` и `moderator`.
- [x] **Нет блокировки входа по учётке.** Лимит — 5 попыток в минуту с одного
  IP; с пулом адресов пароль перебирается без ограничений.
  Где: `/auth/login` в `apps/api/src/modules/auth/routes.ts`.
  _Сделано 15.11.2026, не закоммичено._ 10 неудачных попыток за 15 минут закрывают вход по этому email на остаток окна (`modules/auth/login-guard.ts`). Обратная сторона: чужими попытками можно на 15 минут закрыть вход владельцу; сброс пароля письмом при этом работает.
- [ ] **Лимит раскрытия контактов — только по IP.** 20 в час с адреса; с пулом
  адресов (IPv6-подсеть, прокси) обходится, а это единственная защита от сбора
  базы контактов. Варианты: считать IPv6 по /64, добавить лимит на анкету в
  сутки, капчу после порога.
  Где: `apps/api/src/modules/profiles/reveal.ts`, `modules/company/reveal.ts`.
  _Частично, 15.11.2026:_ лимиты запросов по всему API считают IPv6 по
  подсети /64 (`rateLimitKey` в `plugins/security.ts`). Лимит на анкету в
  сутки не делался намеренно: им можно было бы выключить чужую анкету,
  исчерпав её квоту. Остаются прокси-пулы IPv4 — против них нужна капча.
- [x] **Секреты в проде не проверяются на старте.** `IP_HASH_SALT`,
  `INTERNAL_API_TOKEN`, `REVALIDATE_SECRET`, `S3_SECRET_KEY` имеют дев-значения
  по умолчанию, и API запустится с ними, если переменная выпадет из `.env`.
  Сделать: при `NODE_ENV=production` падать на старте, если значение пустое или
  дефолтное. Где: `apps/api/src/env.ts`.
  _Сделано 15.11.2026, не закоммичено._ api падает на старте без `IP_HASH_SALT`, `INTERNAL_API_TOKEN`, `REVALIDATE_SECRET`, `S3_SECRET_KEY`; jobs — без `S3_SECRET_KEY`. **Перед выкатом убедиться, что первые три заданы в `.env` на сервере.**
- [ ] **Медиа раздаются с основного домена.** `/media/*` — тот же origin, что
  сайт и API (`infra/caddy/Caddyfile`). Сейчас туда попадают только
  перекодированные webp и mp4, поэтому это не дыра, но любой будущий файл «как
  есть» (SVG, HTML) станет XSS. Надёжнее отдельный домен для медиа.

### P3

- [ ] **Образы без версий.** `minio/minio:latest`, `minio/mc:latest`,
  `boky/postfix:latest` в `docker-compose.yml` — пересборка может молча
  притащить другую версию. Закрепить теги.
  _Проверено на сервере 15.11.2026._ Образов `minio/minio` и `minio/mc` в
  Docker Hub больше нет (реестр отвечает 404 / «access denied»; `caddy` и
  `boky/postfix` с того же сервера доступны). Сервер работает на скачанных
  ранее копиях, **заново их взять негде**:
  - `minio/minio@sha256:14cea493d9a34af32f524e538b8346cf79f3321eff8e708c1e2960462bd8936e`
    (RELEASE.2025-09-07T16-13-09Z);
  - `minio/mc@sha256:a7fe349ef4bd8521fb8497f55c6042871b2ae640607cf99d9bede5e9bdf11727`.

  Сделано: `minio-init` переведён на образ `minio/minio` (в нём есть `mc`),
  зависимость от `minio/mc` убрана.
  Осталось:
  - сохранить образ хранилища вне сервера:
    `docker save minio/minio:latest | gzip > minio-2025-09-07.tar.gz`;
  - решить, на чём хранилище живёт дальше (свой реестр, сборка из исходников
    или другой S3-совместимый сервер) — обновлений безопасности для этого
    образа не будет;
  - закрепить остальные образы по тому, что стоит на сервере:
    `boky/postfix@sha256:aafc772384232497bed875e1eb66b4d3e54ba1ebc86e2e185a6dc1dbc48182ef`,
    `caddy@sha256:5f5c8640aae01df9654968d946d8f1a56c497f1dd5c5cda4cf95ab7c14d58648`,
    `postgres@sha256:18cfe3ef5e6815560c98237d6216d1e5119702fb0f3894c8785dd58b8bbe5d73`,
    `redis@sha256:ff02b58f971e7d7d156a1267e283fcbbeee91773b6aa36c49dac28ecfe28eadf`.
    Смена строки образа пересоздаёт контейнер — делать в окно обслуживания.

- [x] **Регистрация выдаёт занятый email по времени ответа.** На занятый адрес
  ответ быстрее: хэш пароля не считается. Сделать: считать хэш в обеих ветках.
  Где: `/auth/register`.
  _Сделано 15.11.2026, не закоммичено._ Хэш считается в обеих ветках.
- [x] **Старые ссылки сброса пароля не гасятся.** Ни при запросе новой, ни
  после смены пароля; живут час. Где: `/auth/password-reset/*`.
  _Сделано 15.11.2026, не закоммичено._ Гасятся при запросе новой ссылки, при сбросе и при смене пароля из кабинета.
- [ ] **При зачислении платежа не сверяется оплаченная сумма.** У Paymento
  сверяется номер заказа, сумма — нет; полагаемся на статус в подписанном
  колбэке. Где: `settleCallback` в `apps/api/src/modules/billing/topups.ts`.
  _Не сделано:_ нужен реальный ответ `/payment/verify` от Paymento, чтобы
  знать, в каком поле и в каких единицах приходит сумма; угадывать нельзя —
  ошибка здесь означает незачисленные платежи.
- [x] **`/me/favorites` без входа отвечает 500 вместо 401 — находка ошибочная.**
  На маршрутах стоит `requireRole('client')`, без сессии он отвечает 401.
  Править нечего.

- [x] **P2. Скрытое видео доступно по прямой ссылке — оставлено как есть.** Когда

  `Cache-Control: immutable` на год (у фото так же). Если появится CDN, после
  отклонения нужна инвалидация.

  оба проходят проверку, и у анкеты оказывается два видео. Вреда мало

  _Сделано 15.11.2026, не закоммичено._ Лимит перепроверяется в транзакции под замком на анкету (`pg_advisory_xact_lock`), без уникального индекса и миграции. С живой базой не проверялось.

  загрузке не проверяется (у фото так же). Наружу не попадёт, но занимает
  хранилище и очередь модератора.
  _Сделано 15.11.2026, не закоммичено._ Загрузка видео в заблокированную анкету отвечает 403. У фото поведение не менялось.

## 4. Видео анкеты: оптимизация

- [x] **P1. Обработка занимает все ядра процесса API.** ffmpeg работает 10–30
  секунд на ролик, и на маленьком сервере это ударит по скорости ответов.
  Быстрый вариант — ограничить потоки (`-threads 2`, одна строка в
  `ffmpeg.ts`). Надёжный — вынести обработку в контейнер `jobs` с очередью в
  Redis.
  _Сделано 15.11.2026, не закоммичено._ Сделан быстрый вариант: ffmpeg ограничен двумя потоками (декодер, фильтры, кодировщик). Перенос в контейнер `jobs` не делался.
- [x] **P2. Лишний круг через хранилище.** Исходник загружается в S3, а затем
  тот же процесс скачивает его обратно для перекодирования — до 100 МБ лишнего
  трафика на ролик. Обрабатывать прямо из временного файла, копию в S3 держать
  только для восстановления после сбоя. Где: `routes.ts` и `processVideo` в
  `service.ts`.
  _Сделано 15.11.2026, не закоммичено._ Обработка берёт исходник из временной папки загрузки; копия в S3 остаётся для повтора после перезапуска.
- [x] **P3. Ошибки распознаются по русскому тексту.** Кабинет отличает
  «слишком длинное» от «плохой формат» по слову «длиннее» в сообщении сервера
  (у фото — по слову «размера»). Перейти на коды ошибок.
  Где: `VideoManager` и `PhotoManager` в `apps/web/src/modules/account/`.
  _Сделано 15.11.2026, не закоммичено._ Сервер отдаёт коды `video_too_long`, `video_bad_format`, `video_too_large`, `photo_too_large`, `photo_bad_format`; кабинет смотрит на них.
- [x] **P3. Проверка ffprobe запускается в запросе загрузки.** Каждая загрузка
  порождает процесс прямо в обработчике. Сейчас сдерживает лимит запросов; при
  росте нагрузки нужно ограничение числа одновременных проверок.
  _Сделано 15.11.2026, не закоммичено._ Одновременно идут не больше двух проверок, остальные ждут.

# Noova

Каталог-классифайд анкет для взрослых (18+), легальная модель для рынка Германии.
Продуктовый контекст, дизайн-принципы и ограничения — в
[documentation/architecture.md](documentation/architecture.md).
Роадмап — в [documentation/planning.md](documentation/planning.md).

## Стек

| Слой | Решение | Почему |
|------|---------|--------|
| Фронтенд | Next.js 16 (App Router), React 19 | SSR/ISR даёт ботам готовый HTML, навигация остаётся клиентской — SPA-ощущение без потери SEO |
| Стили | CSS Modules + `tokens.css` | Разметка прототипов переносится 1:1, тема переключается одним атрибутом без рантайма |
| i18n | next-intl, префиксы `/de` `/en` `/ru` | Отдельный URL на язык + hreflang; без префикса языки конкурируют в выдаче |
| Бэкенд | Fastify 5 + Prisma 7 + PostgreSQL 17 | Лёгкий, быстрый, схемы запросов и ответов — те же zod-контракты, что у фронта |
| Контракты | `packages/shared` (zod) | Один источник правды: рассинхрон фронта и бэка падает на типах, а не в проде |
| Хранилище | MinIO (S3-совместимое) | Self-hosted и переносимо между провайдерами |
| Прокси | Caddy | Автоматический TLS: на новом домене поднимается без ручной настройки |

## Структура

```
noova/
├── apps/
│   ├── web/                  Next.js — публичный сайт
│   │   ├── src/app/          только маршруты
│   │   ├── src/layout/       шапка, подвал, гейт 18+
│   │   ├── src/modules/      фича целиком: api.ts + components/
│   │   ├── src/design-system/ ui-кит, токены, глобальные стили
│   │   ├── src/overlays/     портал и блокировка прокрутки
│   │   ├── src/shared/       серверный API-клиент, ключи запросов, i18n
│   │   └── messages/         de.json, en.json, ru.json
│   └── api/                  Fastify — публичное API
│       ├── src/modules/      profiles/ promo/ health/
│       ├── src/plugins/      prisma, security
│       └── prisma/           схема, миграции, сид
├── packages/shared/          zod-контракты и доменные типы
├── infra/
│   ├── caddy/                Caddyfile
│   └── backup/               скрипты дампа и восстановления

```

## Требования

- **Node.js 22 LTS** — Prisma 7 не поддерживает нечётные версии (23, 25).
  В репозитории есть `.nvmrc`: `nvm use`.
- pnpm 11 (`corepack enable`)
- Docker с Docker Compose

## Быстрый старт

```bash
nvm use              # Node 22
make setup           # зависимости + Postgres/Redis/MinIO + миграции + демо-данные
make dev             # web на :3000, api на :4000
```

Или по шагам:

```bash
pnpm install
cp .env.example .env
docker compose -f docker-compose.dev.yml up -d
pnpm db:generate && pnpm db:migrate && pnpm db:seed
pnpm dev
```

Открыть: <http://localhost:3000/de> · API-доки: <http://localhost:4000/docs>

Учётные записи для проверки —
[documentation/test-credentials.md](documentation/test-credentials.md)
(`pnpm --filter @noova/api db:seed:dev-users`).

## Команды

```bash
pnpm dev              # web + api параллельно (гасит прежние процессы, см. ниже)
pnpm dev:stop         # остановить процессы разработки этого проекта
pnpm dev:web          # только фронт
pnpm dev:api          # только бэк
pnpm build            # сборка всех пакетов
pnpm typecheck        # типы во всём монорепо
pnpm lint             # Biome
pnpm db:migrate       # применить миграции
pnpm db:seed          # демо-данные
pnpm db:studio        # Prisma Studio
make help             # весь список
```

## Развёртывание на сервере

Полное руководство — [documentation/deployment.md](documentation/deployment.md):
что нужно кроме сервера, мощности, DNS для почты, заполнение `.env`,
осмотр базы и бэкапы. Коротко:

Весь стек — контейнеры, поднимается одной командой на любой машине с Docker.

```bash
git clone <repo> && cd noova
cp .env.example .env      # заполнить домен и секреты
docker compose up -d --build
```

Что произойдёт:

1. Стартуют Postgres, Redis, MinIO с проверками готовности.
2. Одноразовый контейнер `migrate` накатывает миграции — до старта `api`.
   Отдельным сервисом, потому что при нескольких репликах `api` миграции
   подрались бы за блокировку.
3. `api` поднимается только после успешных миграций, `web` — после того как
   `api` прошёл healthcheck.
4. `caddy` выпускает TLS-сертификат для `SITE_DOMAIN` и проксирует трафик.
   Наружу открыт только он — остальные сервисы портов не публикуют.

### Переезд на другой домен

Поменять `SITE_DOMAIN` / `SITE_URL` в `.env` и перезапустить:
`docker compose up -d --force-recreate caddy web`. Сертификат выпустится сам.

## Устойчивость к отказам

- `restart: unless-stopped` на всех сервисах.
- Healthcheck у каждого сервиса; `depends_on` ждёт готовности, а не только старта.
- API подключается к БД с ретраями и экспоненциальной паузой — порядок старта
  контейнеров не имеет значения.
- `/healthz` (liveness) и `/readyz` (readiness, проверяет БД) для оркестратора.
- Graceful shutdown: при SIGTERM Fastify дослыает текущие ответы и закрывает
  пул соединений, с принудительным выходом через 10 секунд.
- `under-pressure` отдаёт 503 при перегрузке вместо падения по памяти.
- Rate limiting и Helmet на всех публичных маршрутах.
- Ротация логов (10 МБ × 5 файлов), иначе диск заполняется незаметно.

## Бэкапы

Контейнер `backup` делает `pg_dump` по расписанию (`BACKUP_INTERVAL_SECONDS`,
по умолчанию раз в сутки) в `./backups/`, с ротацией на `BACKUP_KEEP_DAYS` дней.
Дамп пишется во временный файл и переименовывается в конце — оборванный
процесс не оставит битый файл, выглядящий как валидный.

```bash
make jobs                                          # чистка по срокам хранения
make backup                                        # дамп прямо сейчас
make restore DUMP=backups/noova-20260819T120000Z.sql.gz
```

Восстановление перезаписывает текущую БД и требует подтверждения `yes`.

> Дампы содержат персональные данные особой категории по GDPR. Каталог
> `backups/` в git не попадает; на сервере его нужно шифровать и хранить
> отдельно от основной машины.

## Что уже готово

- Монорепо, общие zod-контракты, генерация Prisma-клиента.
- Главная: промо-слайдер, две секции карточек, счётчики, скелетоны загрузки.
- Страница анкеты: галерея, сворачиваемые секции, тарифы, параметры, услуги,
  «анкеты рядом», JSON-LD.
- Header/Footer, переключение темы (кука + инлайн-скрипт, без вспышки) и языка.
- i18n на трёх языках, hreflang, sitemap из живых данных, robots.txt.
- API: листинг с фильтрами и курсорной пагинацией, страница анкеты, промо-слоты,
  OpenAPI-доки на `/docs`.
- Возрастной гейт 18+ (N-01).
- Аккаунты: регистрация по email, вход, роли, сессии в Redis, сброс пароля,
  подтверждение адреса (N-02), состояние сессии в шапке (N-16).
- Кабинет владельца: создание и редактирование анкет, тарифы, услуги из
  справочника, отправка на проверку, публикация (N-04).
- Фотографии: загрузка с вычисткой EXIF, три размера, порядок, удаление,
  полноэкранный просмотр, разделение доступа pending/public (N-05).
- Сброс кэша по событию: правки владельца видны сразу, ISR сохраняется (N-17).
- Модерация: очередь фото и верификаций, журнал решений, управление
  сотрудниками, счётчик в шапке (N-06).
- Почта: SMTP, письма на трёх языках, очередь с повторами; локально Mailpit
  на <http://localhost:8025> (N-15).
- Параметры внешности перечислениями и фильтры по ним (N-11).
- Каталог `/catalog/[kind]`: панель фильтров, состояние в URL (N-12).
- Пагинация: «Показать ещё» — ссылка `?page=N`, которую перехватывает JS,
  так что каталог обходится ботом и не перезагружается человеком (N-13).
- Контакты с гейтом показа: в разметке их нет вовсе, значения приходят
  отдельным маршрутом по нажатию, с лимитом и журналом раскрытий (N-08).
- Избранное у клиента: сердце на карточке и в анкете, страница
  `/account/favorites`, нажатие гостя применяется после входа (N-09).
- Фоновая чистка по срокам хранения: отдельный сервис `jobs`, замок в Redis,
  сроки в конфигурации (N-18).
- Отзывы клиентов с премодерацией: жалоба вместо публичного ответа, без
  числового рейтинга (N-10).
- Жалобы на анкету без входа, срочные причины отдельной вкладкой у
  модератора (N-23); журнал решений отдельной страницей (N-24).
- Блокировка анкеты с причиной и путём исправления, блокировка учётной
  записи, списки заблокированных анкет и учётных записей (N-25).
- Карта района на странице анкеты: область без маркера, плитки через
  собственный домен; владелица ставит точку сама, сервер огрубляет её
  до ~1 км (N-14).
- Каталог на карте: точки-группы по районам, общие фильтры со списком (N-26).
- Удаление анкеты и учётной записи: подтверждение паролем, отсрочка
  у аккаунта, стирание файлов из хранилища (N-27).
- Страницы «О проекте», «Размещение анкеты», «Контакты» на трёх языках (N-28).
- Клиентские запросы через TanStack Query, ключи в одном модуле (N-19);
  каждый компонент — в своей папке (N-20); фича — одной папкой в
  `src/modules/`, оверлеи через общий портал (N-22).

невыполненной к публичному запуску — без `Impressum` и `Datenschutz` на
рынке Германии открываться нельзя.

`pnpm --filter @noova/api db:create-admin <email> <пароль>`. Дальше он заводит
модераторов в разделе `/admin`.
